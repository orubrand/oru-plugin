# Getting started with Oru

Oru's link lists a short set of tools first: an Orubrand tool named here that is not in your list runs through `use_tool` (its name and its arguments), and `more_tools` says what it takes. Figma's and Oru Connect's tools belong to their own servers and never go through `use_tool`: if they are missing, that server is not connected.

Never show the person a checklist, a list of sources or a form, never ask more than one thing at once, and never ask for a password or a token in the chat. An agent without the plugin gets the same steps as Orubrand's `setup` prompt.

1. **Is Oru connected?** Call `get_setup_status`. If the plugin's `plugin:oru:orubrand` server (or an `orubrand` server added by hand) is listed under `/mcp` as needing authentication, have the user run `claude mcp login plugin:oru:orubrand` in a terminal, or open `/mcp`, pick it and choose **Authenticate**, and sign in with their Orubrand account. That one sign-in is all: the hooks get their key when the machine is linked (step 3), with nothing to paste. With an access key instead, Orubrand's **Connect your agent** page has the exact command for their agent.
2. **Tie this folder to a project.** `get_setup_status` with the folder's value says the project it is tied to; when it answers `needsBinding`, run `list_projects` through `use_tool`, ask which and call `link_this_machine` (see the `oru` skill).
3. **Conversations, without asking.** Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/oru.mjs" status` (the `conversations` skill). If this machine is not linked (`keySet` false) and you signed in to Orubrand here, link it now **without asking**, since it is the same account: call `link_this_machine` and immediately run `node "${CLAUDE_PLUGIN_ROOT}/scripts/oru.mjs" link <code> --url <url>` with the `hooksKey` and `url` it answered. Never show the code.
4. **One offer at a time.** `get_setup_status` gives `onboarding.next`, the one thing to offer now, with what to say in `say`, and `connectors`, where each source stands. Find out yourself what is connected; never ask the user whether something is.
   - **a source**: offer it with what Oru would learn and its `connectUrl`, which opens in their browser; they sign in once, read only, and come back.
   - **Figma**, which has no link: Oru never calls Figma, so you read it with their own Figma access and push it (the `sync` skill). With the Figma MCP server's working tools, call its `whoami`: connected as the account it names. Only an `authenticate` tool, or `whoami` fails: not signed in, so call its `authenticate` tool and give the user the sign-in link it returns; when they confirm, call `whoami`. If they paste a `localhost` callback address instead, pass it to its `complete_authentication` tool. Not installed: ask, then in Claude Code run `claude mcp add --transport http figma https://mcp.figma.com/mcp`; in Codex run `codex mcp add figma --url https://mcp.figma.com/mcp && codex mcp login figma`. A server just added may need a restart of the agent: say so, and that running setup again picks up where it left off;
   - **the first read of a source they just connected**: signing in only saves the connection, so offer once to start Oru reading it, with what it would learn, and on their yes run what its `say` names (the picker first when there is one), through `use_tool` when it is not in your list;
   - **their other AIs**: offer once, naming them, and give exactly the steps of the one they name;
   - **a line that confirms** what Oru learned from what is connected, ending with "Right?", instead of asking what they do;
   - **one question** from Oru's bank, only at a natural pause.
5. **Keep the answer.** Call `onboarding_answer` with `done` or `later`: it gives the next offer. Make it the same way, until there is none. A source in `onboarding.notHere` is not offered here: say why if they ask, and never give a link for it.
6. **Choose what to index, when they want to.** For a connected source, ask for the folders, sites, channels or calendars that matter, one at a time (`microsoft_sources` lists the OneDrive folders and SharePoint sites they can read; `list_slack_channels` the channels; `list_calendars` the calendars). Then `sync_drive_source`, `sync_microsoft_source`, `sync_slack_channel` or `sync_calendar` for each, and `sync_gmail` for their email, which Oru keeps as a summary per day with links to each thread, never the emails' words: Oru reads it in the background and skips what did not change. `get_sync_state` reports what is indexed, what failed and what Oru could not read (named, never skipped silently).
7. **The company file server**, only when they ask for it: the `connect` skill. A folder: `node "${CLAUDE_PLUGIN_ROOT}/connect/oru-connect.mjs" add-source --name <name> --type fs --root <folder> --project <projectId>`; an SFTP server with a password: the user runs its `add-source ... --password-stdin` in their own terminal, never through you. Then `node "${CLAUDE_PLUGIN_ROOT}/connect/oru-connect.mjs" doctor`, and restart the `oru-connect` server from `/mcp` so it reads the new source: say so, and that running setup again picks up where it left off.
